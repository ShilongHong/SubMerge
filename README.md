# SubMerge：Clash 订阅合并

把多个机场订阅（远程链接或本地文件）合并成**一个永久的 Clash 订阅链接**。自托管，一个网页就能配置，以后增减订阅只需回来修改，客户端里的链接不用换。

## 适合什么场景

同时用着好几家机场，你大概遇到过这些麻烦：

- 客户端里挂着好几个订阅，想换一家的节点就得切整份配置，分流规则也跟着变。
- 一家机场的分流规则好用，另一家的节点更快，没法同时用上。
- 手机、电脑、路由器每台都要各加一遍订阅；换机场时每台再改一遍。
- 某家机场临时挂了，整份配置就不能更新了。

SubMerge 放在你自己的服务器上，替你把这些订阅拉下来合成一份配置：

- 所有订阅的节点都在同一份配置里，按订阅分好组，任何分流规则都能选任意订阅的节点。
- 每台设备只需添加 SubMerge 给出的一个链接。以后改订阅是在网页上改，客户端「更新订阅」就生效。
- 除「分流规则来源」外，其他订阅下载失败时会被跳过；每次成功下载都会留缓存，失败时用缓存兜底。

## 能做什么

| 功能 | 说明 |
|---|---|
| 多订阅合并 | 数量不限；支持远程链接，也支持上传文件（Clash YAML、Base64、节点链接列表） |
| 节点来源一目了然 | 节点统一改名为 `[订阅名]_原节点名`，重名自动加 `_1`、`_2`，每个订阅单独成组 |
| 两种规则输出 | 同一份节点给出两个链接：**V1** 沿用机场规则，**V2** 使用内置固定规则 + SuperSub 总开关 |
| 流量信息 | 客户端显示指定订阅的剩余流量和到期日；各订阅用量列在「节点信息」分组 |
| 自动测速 | 可为任意订阅生成 `订阅名_Auto` 测速组，自动选延迟最低的节点 |
| 控制参与分流 | 备用或测试用的订阅可以只放在自己的分组里，不混进分流组 |
| 永久链接 | 用 Token 标识一份配置，改配置不改链接 |
| 订阅检测 | 保存后自动检测每个订阅能否获取、有多少节点、剩余流量 |
| 协议解析 | 节点链接支持 vless、vmess、ss、trojan、hysteria2 / hy2 |

## 快速开始

```bash
pip install -r requirements.txt
python app.py
```

打开 <http://127.0.0.1:5000>。所有数据写在启动时的当前目录下，请在项目根目录运行。

可以用环境变量调整监听：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SUBMERGE_HOST` | `0.0.0.0` | 监听地址 |
| `SUBMERGE_PORT` | `5000` | 端口 |
| `SUBMERGE_DEBUG` | 关 | 设为 `1` 开启 Flask 调试 |
| `SUBMERGE_RELOAD` | 开 | 设为 `0` 关闭代码热重载 |

要从外网访问，建议放在 Nginx 等反向代理后面并开启 HTTPS：订阅链接里带着 Token，明文传输容易泄露。

## 使用方法

### 新建

1. **添加订阅源**：填写名称（会成为节点前缀和分组名，建议用简短的机场名），粘贴订阅链接或上传文件。有几个订阅就点几次「添加订阅」。
2. **合并设置**：选择「分流规则来源」和「流量信息来源」。只有一个订阅时保持默认即可。
3. **保存并生成链接**：右侧（手机上在下方）会给出 V1、V2 两个链接和 Token。复制链接添加到客户端，或点「导入 Clash」直接唤起客户端。

保存后页面会自动检测每个订阅：能否获取、解析出多少节点、剩余流量。标红的订阅需要检查链接。

### 修改

点右上角「修改已有订阅」，输入 Token 或直接粘贴订阅链接即可载入。浏览器会记住最近用过的几个配置，也可以用「复制修改页链接」收藏一个 `/?token=…` 地址，打开即载入。

改完点「保存修改」，订阅链接不变，在客户端里更新一次订阅即可。

> Token 无法找回。它和订阅链接一样等同于密码：拿到它就能看到你的全部订阅地址，请勿公开分享。

## 选项说明

### 每个订阅

| 选项 | 默认 | 作用 |
|---|---|---|
| 名称 | `订阅N` | 节点前缀、订阅分组名。不能重名，不能含逗号，不能和内置分组同名 |
| 节点参与分流 | 开 | 开：节点出现在各分流组（如 YouTube、ChatGPT、漏网之鱼）的候选里。关：只出现在本订阅自己的分组里（V2 中也会在 SuperSub 里） |
| 自动测速组 | 关 | 额外生成 `名称_Auto`（url-test，每 5 分钟测速） |

### 合并设置

| 设置 | 作用 |
|---|---|
| 分流规则来源 | V1 使用这个订阅的分流规则、代理组以及其他顶层配置。**它获取失败且没有缓存时，整个合并订阅都会失败**，请选最稳定的一个 |
| 流量信息来源 | 客户端订阅列表里显示哪个订阅的剩余流量和到期日。默认跟随分流规则来源 |

## V1 和 V2 的区别

两个链接的节点、订阅分组、测速组和流量信息完全相同，只有**代理组和分流规则**不同。可以同时导入对比，随时切换。

| | V1：沿用机场规则 | V2：固定规则 + SuperSub |
|---|---|---|
| 链接 | `/api/subscribe?token=…` | `/api/subscribe/v2?token=…` |
| 分流规则 | 来自「分流规则来源」订阅，前面插入内置的广告拦截、视频广告、TikTok、学术网站、挑剔网站、下载规则 | 固定使用 `templates_storage/v2_rules.json`，不随机场变化 |
| 代理组 | 机场原有代理组（加入参与分流的节点）+ 内置分组 | 模板分组，名称统一以 emoji 开头：🧲 海外AI、🌍 国外媒体、📲 电报信息、🎬 Netflix、🐟 漏网之鱼、🎯 绕过代理等 |
| 总开关 | 无 | 最上方的 **SuperSub**：先列各订阅组和测速组，再列全部节点。代理类分流组默认选 SuperSub，所以切换 SuperSub 就能整体换线路 |
| 更新方式 | 每次都重新下载，失败时用缓存 | 缓存优先（见下文），客户端更新更快 |
| 适合 | 喜欢原机场分组和规则 | 想要一套稳定、分组更全的规则，且常在多家机场之间切换 |

V2 的一些细节：

- `Ⓜ️ 微软服务`、`🍎 苹果服务` 默认直连；`🎯 绕过代理`、`🛑 广告过滤`、各广告组、`🚧 屏蔽访问` 保持直连或拦截。
- `PASS` 策略只对 mihomo 内核的客户端加入（按 User-Agent 识别 Clash Verge、Clash Meta、mihomo party、FlClash、Nyanpasu），旧版 Clash 内核不认识它。
- 要修改 V2 规则，直接编辑 `templates_storage/v2_rules.json`。规则目标只能是模板中的分组、`SuperSub`、`DIRECT`、`REJECT` 或 `PASS`。

## 更新与缓存

每次成功下载的订阅都会解析后缓存在 `subscription_cache/`。

- **V1**：客户端每次更新都重新下载所有订阅；某个订阅下载失败时使用它的缓存。
- **V2**：15 分钟内的缓存直接返回；14 天内的缓存先返回，同时在后台刷新；更旧的才同步下载。在 V2 链接后加 `&refresh=1` 可强制重新下载。

## 合并后的配置长什么样（V1）

```text
proxies:        所有订阅的节点，改名为 [订阅名]_原节点名
                + 流量信息占位节点（127.0.0.1:1，仅用于显示用量）
proxy-groups:
  机场A / 机场B …        每个订阅一个 select 组
  机场A_Auto …           开启自动测速的订阅
  节点信息                各订阅的剩余流量和到期日
  下载、挑剔的网站、TikTok解锁、屏蔽视频广告、常见广告域名、BLOCK、🌏 学术网站
  机场原有的代理组        加入所有「参与分流」的节点；与内置组重名时加 _group 后缀
rules:          内置规则 + 分流规则来源的规则（指向不存在分组的规则会被丢弃）
其他顶层配置:    来自分流规则来源订阅；DNS 使用内置配置
```

## API

网页用到的接口，也可以直接调用。

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/create` | 新建配置（`multipart/form-data`）。带上已存在的 `token` 时等同于更新 |
| `GET` | `/api/config/<token>` | 读取配置 |
| `PUT` | `/api/config/<token>` | 更新配置，保留配置中其他未知字段 |
| `GET` | `/api/check/<token>` | 逐个检测订阅：是否成功、节点数、流量信息。加 `?refresh=1` 强制重新下载 |
| `GET` | `/api/subscribe?token=` | V1 订阅（Clash YAML） |
| `GET` | `/api/subscribe/v2?token=` | V2 订阅（Clash YAML），支持 `&refresh=1` |

`/api/create` 的表单字段按序号编号（`N` 从 0 开始）：

| 字段 | 说明 |
|---|---|
| `token` | 可选。已存在则更新该配置 |
| `sub_name_N` | 订阅名称 |
| `sub_url_N` | 订阅链接（上传文件时留空） |
| `sub_file_N` | 订阅文件 |
| `file_md5_N` | 已上传文件的 MD5，更新时沿用旧文件 |
| `is_main_N` | `true` 表示分流规则来源 |
| `traffic_main_N` | `true` 表示流量信息来源 |
| `in_rules_N` | `true` 表示节点参与分流 |
| `enable_auto_N` | `true` 表示生成自动测速组 |

返回：

```json
{
  "success": true,
  "token": "…",
  "subscribe_url": "https://example.com/api/subscribe?token=…",
  "subscribe_url_v2": "https://example.com/api/subscribe/v2?token=…"
}
```

## 数据与备份

运行时数据都在项目目录下，已被 `.gitignore` 忽略：

| 目录 | 内容 |
|---|---|
| `configs/` | 每个 Token 一个 `{token}.json`。删除文件即删除该配置 |
| `uploaded_files/` | 上传的订阅文件，以内容 MD5 命名 |
| `subscription_cache/` | 已解析的订阅缓存，可随时删除 |

备份 `configs/` 和 `uploaded_files/` 即可完整迁移。
